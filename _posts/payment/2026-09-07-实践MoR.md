**MoR = Merchant of Record**，中文通常可以理解为**名义商户 / 记录商户 / 法定交易商户**。

简单说，MoR 是在一笔交易中，**法律和支付层面作为“卖家”直接面对消费者的主体**。消费者的银行卡账单上，通常体现的是 MoR 或与其相关的商户名称，而不一定是实际提供商品/服务的原始商家。

举个例子：

中国商家 A 想把商品卖给英国消费者，但自己不想处理英国本地收单、税务、退款、拒付等复杂问题，于是接入 MoR 平台 B：

**消费者 → 向 B 付款 → B 向消费者销售商品 → B 再与商家 A 结算**

这时候 B 就是 **Merchant of Record**。

MoR 通常不仅仅是“帮商家收钱”，而是会承担更多交易责任，例如：

- 作为消费者交易的销售主体
- 接受 Visa/Mastercard 等支付
- 处理退款、拒付（Chargeback）
- 承担支付欺诈风险
- 处理 VAT / Sales Tax / GST 等税务
- 开具发票或交易凭证
- 处理消费者投诉
- KYC/KYB、AML 等相关合规义务
- 最终再与实际供应商/商家进行结算

**和普通 Payment Gateway / PSP 最大的区别**

假设消费者花 **£100** 买中国商家的一件商品。

**普通 PSP 模式：**

```
消费者 → £100 → 中国商家
```

PSP 只是提供支付能力，**真正卖家仍然是中国商家**。

**MoR 模式：**

```
消费者 → £100 → MoR → 扣除税费/服务费 → 中国商家
```

消费者法律意义上的交易对手通常变成了 **MoR**。

所以核心区别可以概括成：

> **PSP 是“帮你收钱”，MoR 更接近“以自己的名义帮你卖”。**

这也是为什么 MoR 模式在**游戏、SaaS、数字内容、跨境电商、AI 服务**等领域很常见。

例如海外消费者想购买淘宝上的 ¥1,000 商品，可以设计成：

**英国消费者 → GBP付款给海外MoR → MoR完成中国商品采购 → 中国供应商/代购 → 国际物流 → 英国消费者**

这样就不只是“跨境支付”问题了，而变成了**谁是卖家、谁承担退款/拒付、谁负责VAT、谁承担商品责任、资金如何跨境结算**的问题。
